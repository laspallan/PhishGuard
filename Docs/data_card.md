| Source | Type | Label | What we take | Terms / licence |
|---|---|---|---|---|
| PhishTank `online-valid.csv` | URL | phishing | verified rows; `submission_time` → `source_date` | Cisco terms of use (linked from the PhishTank page); asks for User-Agent `phishtank/<username>`; without an app key "a few downloads per day" |

| SpamAssassin public corpus 2003 ham (`easy_ham`, `easy_ham_2`, `hard_ham`) | email | legitimate | 4,150 messages; spam not used | copyright stays with the original senders; hostnames obfuscated |

| Own mailbox check set | email | legitimate | `.eml` files you export to `data/raw/own_mailbox/` | evaluation only, never in the dataset |

Raw files are never published. The scripts in `ml/` rebuild everything from the sources.

## Labelling (decision D1)

Attack categories come from ordered rules in `ml/phishguard_ml/data/label.py`, using the
shared word lists in `backend/phishguard/services/features/lexicons.py`:
malware → brand_impersonation → credential_harvest → spear → unknown. URL rules that need
the page (password field, login form, page title) only work after the URL has a snapshot, so
URL categories must be recomputed after snapshotting.

## Known issues and biases

- **Email age gap** (proposal §3.6.1): legitimate emails are from 2001–2003, most phishing
  emails from 2005–2025. Handled by `email_normalise.py`, the no-F96–F101/F109/F110 check and
  the recent own-mailbox check set.
- **Tranco URLs are home pages only** (`https://<domain>/`), while phishing URLs usually have
  paths and queries. A model can separate the classes by URL shape alone. See decision D10.
- **PhishTank only lists phishes that are still online.** Its `submission_time` nevertheless
  spans 2011–2026 (most 2023–2026), see the statistics below and decision D9.
- **Registration data (RDAP)** comes from each registry's own RDAP server (`data/rdap/`), not
  from the snapshot; some registries (many country TLDs) have no RDAP server.
- **Snapshots are taken when a URL is collected.** Pages that were already offline have no
  HTML features; the snapshot coverage is reported below.
- **Some Nazario dates are wrong** (years 1970, 2030, 2038): broken `Date` headers in the
  original messages. `source_date` is only descriptive and not used for the split.
